# docs/ — Documentation

Human-readable documentation. Nothing here is machine-consumed, so prose is fine.

## Subfolders

| Folder          | Contents                                                                 |
| --------------- | ------------------------------------------------------------------------ |
| `guides/`       | Beginner-friendly how-to guides (how to run the project, how to use Git) |
| `reports/`      | Session completion reports, one file per major work session              |
| `architecture/` | Architecture notes, diagrams, and design rationale                       |

## Rules

- Documentation is not a substitute for the governance ledgers at the repository
  root. Status of work lives in `PROJECT_STATE.md` and `TASK_LEDGER.md`, not here.
- Completion reports in `reports/` are append-only. Do not rewrite history; write
  a new report instead.
- Report filenames use the format `YYYY-MM-DD-short-slug.md`.
